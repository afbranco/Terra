Introduction - TinyOS platforms

In this page we explain:

  • how to get a TinyOS-2.1.2 build environment for Terra,
  • how to compile the firmware for TinyOS version of TerraVM and flash it into a device,
  • how to compile your Terra Script,
  • how to load a Terra Script bytecode in the network, and
  • how to start the Terra grid simulator.

In theory it is possible to compile Terra for all platforms available for TinyOS. But currently Terra has been tested on the following boards:

  • TelosB
  • MicaZ
  • Iris
  • Mica2
  • Mica2Dot

You will find in TerraNet and TerraGrp detailed informations about TerraNet and TerraGrp specific events and functions.

Build environment

There are two ways to get an environment to build and use Terra for TinyOS.

Terra pre-built virtual machine

The Terra virtual machine image (TerraNG_v0.3.0.ova) has TinyOS 2.1.2, the AVR and MSP430 tools, the Terra compiler, the Terra Control tool and the simulator already installed (Ubuntu 12.04, 32 bits). The download and the tutorial can be found at the Terra Site.

TinyOS toolchain container

The tinyos-toolchain project provides TinyOS 2.1.2 and TOSSIM as a container image. Terra compiles inside it without changes. Clone this repository and run the make command inside the container:

git clone https://github.com/afbranco/Terra
cd Terra
podman run --rm -v $PWD:/terra:Z -w /terra/TerraVM/src \
    ghcr.io/afbranco/tinyos-toolchain:2.1.2-resolute-py3 \
    make micaz VM=NET TYPE=ALL

docker can be used instead of podman. In this image the TOSSIM module is built for Python 3 (_TOSSIM.so).

Compiling and flashing

Terra development environment uses a Make system to build and install the firmware. You must change to the TerraVM/src directory and execute make with additional parameters in the form NAME=value. The follow command is an example of Terra compilation and installation for a MicaZ board with node identifier 2, using a MIB520 programmer:

cd TerraVM/src
make micaz VM=NET TYPE=NOBS install.2 mib520,/dev/ttyUSB0

Attention points

  • The TYPE parameter defines the runtime type of the node:
    • NOBS: a regular node, running only the Terra VM;
    • BS: a BaseStation, bridging the radio network and the computer via USB;
    • ALL: both roles in the same firmware (default; mandatory for the simulator).
    Usually one node, the BaseStation, is connected to a computer via USB interface, and the other nodes communicate via radio.
  • The install.n parameter flashes the compiled file. The n is the node identifier. The BaseStation is the node 1.
  • The device path (for example /dev/ttyUSB0) depends on the USB adapter. Its number may change if the previous connection is already allocated. Use the command ls /dev/ttyU* to find the correct port.

Terra compilation parameters

These are the allowed parameters when compiling for a TinyOS board (see the header of TerraVM/src/Makefile).

 VM:      VM flavor: NET or GRP | default NET
 MOD:     Additional modules: FFT,VCN_DAT,VCN_DET,MSGQ | default ''
 SENSOR:  Sensorboard: MTS300CA or MTS300CB(wired) or MDA100 | default MDA100
 QUEUE:   Short or long queues: SHORT or LONG | default SHORT
 TYPE:    Runtime type: BS or NOBS or ALL | default ALL
 HYB:     Hybrid mode, same memory blocks for all boards: YES or NO | default YES
 VERB:    Verbose compilation mode: YES or NO | default NO
 SETDATA: SetData functionality: YES or NO | default NO
 RFPOWER: RF Power: 0 1 2 3 4 5 6 7 | default 4
 LPL:     Low Power Listening mode: YES or NO | default NO

Compiling a Terra script

Terra scripts rely on a definition file targeting a specific customization. The TerraNet.defs file is used for the basic customization and the TerraGrp.defs file is used for the Group customization (both in terrac/samples). One of these files must be referenced in the beginning of your script code as #include "TerraNet.defs".

Use the terrac command to compile your script (in the virtual machine it is already in the path; the distribution TerraDist/TerraNet_v0.3.0/terra has a ready-to-use copy). Assuming that the name of your script file is myScript.terra, type the following command:

terrac myScript.terra

This command will generate a bytecode file named myScript.vmx.

Loading a Terra Script into network

Considering that you already have a script compiled with terrac compiler, you need to load the script bytecode into the Terra network nodes. Two tools must be started to that: the TinyOS SerialForwarder application and the Terra Control tool (TerraDist/TerraNet_v0.3.0/tools/TerraVMControl.jar). The use of the Terra Control tool is explained in the Terra tutorial at Terra Site.

The SerialForwarder is started by java net.tinyos.sf.SerialForwarder -comm serial@path:baud, where path is the path to the USB interface (data port) and baud is the baud rate or the platform name:

java net.tinyos.sf.SerialForwarder -comm serial@/dev/ttyUSB1:micaz
Note: The mica family boards open a second USB port to data communication. For example, a MIB520 USB adapter will open the /dev/ttyUSB0 for firmware flashing and the /dev/ttyUSB1 for the data comunication used by Terra.

Simulating Terra with TOSSIM

The Terra project has a customized grid simulator that allows some tests and experiments. The TOSSIM simulator is used to run a Terra firmware and a simple visual interface was built to represent, as possible, the simulation execution. The simulator module is built with

make micaz sim-sf VM=NET TYPE=ALL

The simulation is started using two scripts: TerraSim.py and TerraViewer.py (in TerraVM/src and in TerraDist/TerraNet_v0.3.0/sim). The first one executes a TOSSIM script and receives as arguments the grid size and execution time. The second executes a graphical network animation based on the output informattion from the TOSSIM execution. After started a simulation, the Terra Control tool must be used to load a Terra script into the network. Note that the SerialForwarder tool is not used.

The following command syntax must be used:

./TerraSim.py lines columns 0 0 time | ./TerraViewer.py

where lines and columns are, respectivately, the number of lines and columns that define the network grid. These numbers can vary from 1 up to 9. The two 0 are constants used for advanced tests and the time is the execution time in seconds that the simulation will run. For example, the command bellow will start a 5 minutes (300 seconds) simulation for a 2x3 grid.

./TerraSim.py 2 3 0 0 300 | ./TerraViewer.py
Note: These scripts were written for Python 2 and the TOSSIM module of the virtual machine. More details how to use the simulation can be found in the Terra Tutorial.
